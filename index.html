Case Study 01
Production AI WhatsApp Agent
Live system. Real client. Real conversations. Feb 2025 – Present.
The Problem

BIM Training & Projects was losing potential leads — people would message their WhatsApp number asking about courses, get delayed responses, and move on. They needed an intelligent system that could respond 24/7, qualify leads, and log everything without manual work. They needed a product, not just a script.

My Approach

I didn't jump to code. I first understood their conversation flows — what questions prospects asked, what information they needed, what qualified them as a lead. Then I designed the entire conversation architecture before touching Python. The tech stack came last, chosen to solve specific constraints: WhatsApp Business API for the channel, FastAPI for the webhook server, Google Sheets as a zero-cost CRM, Railway for deployment.

Challenges I Solved
  • WhatsApp webhook verification fails silently — had to implement proper SSL handling and response timing within Meta's strict 3-second window
  • Railway's free tier sleeps after inactivity — solved with UptimeRobot pings every 5 minutes to keep the server warm
  • Google Sheets API rate limits — implemented request batching and exponential backoff for lead logging
  • Conversation state management — built a session system to track multi-turn conversations without a database

Case Study 02
Smart Product Pricing Prediction
ML pipeline — text + images → price prediction. NLP, feature engineering, 3 models compared, 5-fold CV.
The Problem

E-commerce platforms need accurate price predictions for millions of products — but product prices depend on text descriptions, visual appearance, weight, pack size, and dozens of other signals. The challenge was building a multimodal ML pipeline that extracts all these signals and predicts prices reliably across diverse product categories.

My Approach

Started with EDA — found price distribution was heavily right-skewed, so applied log-transformation before modeling. Then built three parallel feature pipelines: TF-IDF for text (5,000 features + bigrams), regex-based numeric extraction (11 features: weight, pack size, volume, premium keywords), and OpenCV color histograms from product images. Combined all three into a single sparse matrix and trained three algorithms to find the best performer.

Technical Highlights
  • TF-IDF with 5,000 features and bigrams for semantic text representation of product descriptions
  • 11 engineered numeric features extracted via regex — weight (oz/lb/g normalized), pack count, volume, premium keyword score
  • OpenCV color histogram extraction from product images — 24-dim feature vector capturing visual pricing signals
  • Log-transform on target variable significantly improved all model performances by handling outlier prices
  • 5-fold cross-validation confirmed stable, consistent performance across all data splits

Case Study 03
Real-Time Sign Language Recognition
Accessibility tech. Computer vision. Built for SIH — ranked Top 16 nationally.
The Problem

Hearing-impaired individuals face a communication barrier in digital interfaces built entirely around text and voice. We wanted to build a system that reads hand gestures in real time and translates Indian Sign Language into text — bridging that gap without requiring expensive hardware.

My Approach

Used MediaPipe's hand landmark detection to extract 21 key points from each hand frame — converting the visual gesture into a numerical feature vector. Trained a custom ML classifier on those features to recognize ISL gestures. The pipeline runs entirely on a standard webcam, frame by frame, with minimal latency.

Technical Challenges
  • Hand landmark detection fails under poor lighting — implemented adaptive preprocessing
  • Reducing false positives between similar gestures required careful feature selection
  • Real-time performance constraint — optimized the inference pipeline for low latency
  • Building a labeled training dataset for ISL gestures from scratch
